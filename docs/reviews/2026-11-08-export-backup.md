# 数据备份、恢复和导出代码审查

2026-11-08 · 审查人：新上下文子 agent（一轮）· 对象：`feat/export-backup` 相对 `main`

结论：可以合并，没有必须修的问题。恢复只新增、整份校验、重复恢复不多记录，有单测；不联网，权限没有增加。审查人跑了 `npm run check`，对照了 SDK 58 文档和三个模块的 AndroidManifest。

| # | 级别 | 意见 | 处理 |
|---|---|---|---|
| 1 | 需要人判断 | Android 分享面板不一定有"存到本机"，没装网盘的用户存不下备份 | 补上：Android 点备份或导出时，先选"存到手机文件夹"（系统文件夹选择器）或"分享给其他 App"。备份的目的就是能存下来，不算扩大范围 |
| 2 | 建议 | 缓存目录里会累积完整账本的副本，和设计"覆盖同名文件"不一致 | 每次分享前删掉缓存里以前的 `ledger-*` 文件；恢复时的缓存副本读完就删 |
| 3 | 需要人判断 | Expo 默认 `allowBackup: true`，系统自动备份会把数据传到用户的 Google 云端硬盘，和隐私政策"不上传"不一致（已有问题） | 设 `android.allowBackup: false`，和已有的"不联网、不上传"前提一致。备份只走"备份到文件" |
| 4 | 建议 | 恢复只校验类型：`2026-99-99` 能导入，多余字段会存进本机 | 校验日期真实存在，只取 7 个已知字段；加 6 个单测 |
| 5 | 建议 | 设计写 `replaceAll`，实现是 `mergeIn`；"Expo Go 自带"没核实 | 设计改成和实现一致；SDK 58 文档三个模块都标明 "Included in Expo Go" |
| 6 | 建议 | 恢复后马上提示"恢复完成"，万一写入失败又弹"保存失败"，两条提示矛盾 | 不改：AsyncStorage 写入失败概率很低，而且"保存失败"在后，用户能看到真实结果 |
| 7 | 建议 | 真机验证要有人做 | PR 描述列出 v1.2.0 打 tag 前的真机检查项，包括第 1 条的"存到手机文件夹" |
