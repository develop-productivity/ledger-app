# v1.4.0：首次启动隐私同意和 App 内的隐私政策

2026-11-17 · 作者：Claude · 状态：已实现

## 问题

用户决定改走国内应用商店（[决定](../decisions/2026-11-17-china-stores.md)）。国内商店审核会做隐私合规检测，现在的 App 有四处不满足：

1. 首次启动没有隐私政策同意框。
2. 隐私政策只能跳转到 GitHub 网页查看，国内网络经常打不开。
3. 隐私政策没有列出第三方组件（SDK）和用到的系统权限。
4. 没有用户协议，也没有"撤回同意"的入口。

## 方案

### 首次启动的同意页

- 根布局里加一个 `ConsentGate`，放在 `SettingsProvider` 里面（要知道界面语言）、`LedgerProvider` 外面。用户同意之前，不读账本数据，也不显示任何页面。
- 同意页内容：简短说明（不收集信息、数据只在本机）、《用户协议》和《隐私政策》两个链接（点开后在同意页内显示全文）、「同意并继续」「不同意」两个按钮。
- 点「不同意」：提示"需要同意后才能使用"，可以选择「退出应用」（Android 调 `BackHandler.exitApp()`）或「再看看」。iOS 不允许 App 自己退出，只显示提示。
- `BackHandler.exitApp()` 在新版 Android 上是把 App 退到后台，进程不一定结束。再次打开仍是同意页，同意前也没有处理任何数据。真机上确认实际行为；华为要求结束进程时再处理。
- 在同意页里打开协议全文时，按 Android 返回键回到同意页（同意前导航没挂载，要自己处理返回键）。
- **同意前做的事**：只读系统语言和地区（`expo-localization`），读写语言和货币设置（`ledger.settings.v1`），用来按语言显示同意页。不读账本数据，也不碰任何个人信息。

### 同意记录

- 新的 AsyncStorage 键 `ledger.consent.v1`：`{ version: 1, policyVersion: 1, acceptedAt: "2026-11-17T…Z" }`。
- 和账本数据、设置分开存；不进备份文件（同意是这台手机上的行为）。
- `policyVersion` 是隐私政策的版本号，写在代码里。政策有实质变化时加 1，所有用户下次打开 App 要重新同意。
- 读不懂或读失败，按"没同意"处理，再显示一次同意页。宁可多问一次，也不能在没同意时直接进入。

### App 内的政策全文

- `src/i18n/legal.ts`：中英文的隐私政策和用户协议，按"标题 + 段落"组织。和根目录的 `PRIVACY.md`、`TERMS.md` 内容保持一致。
- 隐私政策补上：开发者身份和联系方式、第三方组件清单（Expo 官方模块，都不收集个人信息）、系统权限说明、备份和导出、未成年人、用户权利（查看、导出、删除、撤回同意）、政策变更。
- 页面：`src/app/legal/[doc].tsx`，`doc` 是 `privacy` 或 `terms`。同意页和「我的」都用同一个显示组件 `LegalDocument`。

### 「我的」页面

- 「关于」里的"隐私政策"改为打开 App 内页面，新增"用户协议"。
- 新增"撤回同意"：确认后清除同意记录，回到同意页。本机的记账记录不删除；要删除记录，卸载 App 或清除 App 数据。

### 去掉网络权限（单机 App）

调研（[国内上架调研](../research/2026-11-17-china-stores.html)）：华为把"完全断网时核心功能都能用"的 App 认定为单机 App，可以不填 App 备案号；但"识别到联网场景就无法通过审核"。v1.3.0 的 APK 实际声明了 `INTERNET`（解析 APK 的 AndroidManifest 确认）。

- `app.json` 的 `blockedPermissions` 加上 `android.permission.INTERNET`。正式包（EAS 的 preview、production）不需要网络；调试一直用 Expo Go，不受影响。
- 这推翻了 [2026-11-08 审查](../reviews/2026-11-08-store-prep.md) 第 6 条"保留 INTERNET"的处理：当时的理由是开发版要连 Metro，但项目没有用过开发版。以后要用开发版时，在开发版的配置里单独放开。
- 「我的」里的"源代码"仍然用系统浏览器打开网页，这是浏览器联网，不是 App 联网。

### 开发者信息

华为要求隐私政策写"真实完整有效的开发者信息"，开发者名称要和提交信息一致。个人开发者就是本人姓名。

### 联系方式

国内商店要求隐私政策里写可以联系到开发者的方式。GitHub issues 在国内经常打不开，需要一个邮箱。邮箱属于用户的个人信息，由用户决定填哪个。代码里只有一个常量 `CONTACT`（`src/i18n/legal.ts`），用户给出邮箱前，先写 GitHub issues 链接。**上架国内商店前必须填好开发者姓名和邮箱**，由用户提供。

## 方案对比

| 问题 | 选用 | 没选 | 理由 |
|---|---|---|---|
| 同意前能不能读本地数据 | 不读，同意后才挂载 `LedgerProvider` | 先读数据、只挡住界面 | 检测工具看的是"同意前有没有任何数据处理"，最稳妥的是什么都不做 |
| 同意记录存哪 | 单独的键 `ledger.consent.v1` | 加进 `ledger.settings.v1` | 不改设置的格式；撤回时只清这一个键 |
| 政策全文放哪 | 写进 App（`legal.ts`） | 只放网页链接 | 国内打不开 GitHub；商店检测也要求 App 内能看到 |
| 英文用户要不要也同意 | 一样要 | 只给中文界面加 | 一份逻辑，少出错；海外商店也认可这种做法 |

## 风险和回滚

| 风险 | 处理 |
|---|---|
| 同意记录读失败，用户每次打开都要同意 | 读失败按没同意处理，同意后再写入；写入失败时提示，但这次仍然进入 App |
| `legal.ts` 和 `PRIVACY.md` 内容不一致 | AGENTS.md 加规则：两处一起改；审查时对照 |
| 老用户升级后突然看到同意页 | 正常：国内商店要求所有用户都同意过一次。CHANGELOG 写明 |
| 联系邮箱、开发者姓名还没定 | PR 和发版前检查清单里列出；上架国内商店前必须填。最好在 v1.4.0 发版前填好，省一个补丁版本 |
| 第三方组件清单漏列 | 按 `package.json` 的运行时依赖逐个列出（`react-dom`、`react-native-web` 只用于网页预览，不进 APK）；新增依赖时同步更新 |

回滚：去掉 `ConsentGate`，「我的」改回原来的链接。同意记录是单独的键，留着不影响旧版本。

## 怎么验证

1. 单测：同意记录的解析（没有、坏数据、旧版本政策、当前版本）、"要不要显示同意页"的判断。
2. 网页预览：清空存储后打开，先看到同意页；点两个链接能看全文；同意后进入明细页；刷新后不再出现；在「我的」撤回后回到同意页，记录还在。中英文各走一遍。
3. APK 上：首次安装弹出同意页；看协议时按返回键回到同意页；点「不同意」→「退出应用」，App 回到桌面（记下是退到后台还是结束进程）；从 v1.3.0 覆盖安装后也要先同意一次，原来的记录都在。
4. **提交商店前**：解析 v1.4.0 APK 的 AndroidManifest，确认 `uses-permission` 只剩 `VIBRATE` 和 `DYNAMIC_RECEIVER_NOT_EXPORTED_PERMISSION`，没有 `INTERNET`。
5. 合并后尽快发 v1.4.0：main 上的 `PRIVACY.md` 一合并就写着"已移除网络权限"，而 v1.3.0 的包还带着 `INTERNET`。
