# 数据备份、恢复和导出表格

2026-11-08 · 作者：Claude · 状态：已实现

## 问题

数据只存在手机的应用存储里。卸载 App、换手机、清除应用数据，记录就全没了。上架给陌生人用之前要补上（[上架准备设计](2026-11-08-store-prep.md)的"不做"一节留到了这里）。用户要求放进 v1.2.0 一起发。

## 方案

新增第三个标签页「我的」，放三个按钮和"关于"信息：

| 功能 | 做法 |
|---|---|
| 备份到文件 | 把全部记录写成 JSON 文件。Android 先问存到哪：**存到手机文件夹**（系统文件夹选择器，如「下载」）或**分享给其他 App**；iOS 直接打开分享面板（自带「存储到文件」）。分享前文件先写进缓存目录 |
| 从备份恢复 | 用系统文件选择器选一个备份文件，先显示"将新增 X 条、跳过 Y 条"，确认后合并进本机 |
| 导出表格（CSV） | 全部记录写成 CSV，存法和备份一样，用 Excel、WPS、Numbers 打开 |
| 关于 | 版本号、隐私政策链接、源代码链接 |

新依赖：`expo-file-system`（写、读文件，选文件夹）、`expo-sharing`（分享面板）、`expo-document-picker`（选文件）。都是 Expo 官方模块，SDK 58 文档标明 Expo Go 自带。用系统分享面板和文件选择器，不需要存储权限，上个版本去掉的存储权限不用加回来。

### 备份文件格式（对外格式）

```json
{ "app": "ledger", "version": 1, "exportedAt": "2026-11-08T10:00:00.000Z", "entries": [ ... ] }
```

- `entries` 和本机存储（`ledger.v1`）里的记录完全一样，`version` 跟着存储格式走。以后存储格式升级，恢复时按旧版本迁移。
- 恢复时也接受没有 `app`、`exportedAt` 的文件（就是本机存储的原样）。
- `version` 比 App 认识的大：提示"备份来自更新版本的记账本，请先升级 App"。
- 不是 JSON，或者记录不合法（金额不是正整数分、日期格式不对、日期不存在如 2 月 30 日等）：整份拒绝，不导入一部分。
- 只取记录的 7 个已知字段，多出来的字段不存进本机。

文件名：`ledger-backup-20261108-1000.json`。

### 合并规则

按记录的 `id` 合并：

| 情况 | 处理 |
|---|---|
| 本机没有这个 `id` | 新增 |
| 本机有，内容一样 | 跳过 |
| 本机有，内容不同 | **保留本机的**，跳过备份里的 |

为什么冲突时保留本机：备份是过去某个时刻的快照，本机的记录通常更新。换新手机恢复时本机是空的，不会有冲突。

已知限制：备份之后在本机删掉的记录，恢复时会重新出现。弹窗写明"只新增，不删除本机记录"。

### CSV 格式

列：`日期,类型,分类,金额,备注`。金额用元，两位小数，正数，类型列写"支出"或"收入"。按日期从新到旧。

- 文件开头加 UTF-8 BOM，Excel 打开中文不乱码。
- 字段里有逗号、引号、换行时，加引号并把引号写两遍（RFC 4180）。
- 备注以 `=`、`+`、`-`、`@` 开头时，前面加一个 `'`，防止表格软件把它当公式执行（CSV 注入）。

### 代码结构

- `src/backup.ts`：纯函数 `toBackupJson`、`parseBackup`、`mergeEntries`、`toCsv`、`backupFileName`，配单测。
- `src/exporter.ts`：文件读写、分享、选文件夹、选文件。网页预览里不能分享本地文件，改成浏览器下载。
- `src/dialog.ts`：弹窗。网页预览里 `Alert` 不显示，改用浏览器弹窗，方便在预览里测完整流程。
- `src/app/(tabs)/me.tsx`：「我的」页面。
- `LedgerContext` 加 `mergeIn(incoming)`：在 `setEntries` 里用最新的列表重新合并，只新增，照常走串行保存。

### 方案对比

| 问题 | 选用 | 没选 | 理由 |
|---|---|---|---|
| 备份存到哪 | 系统分享面板，用户自己选 | 自动备份到云端 | 云端要账号和服务器，违反"不联网"的前提 |
| 备份存到哪 | 分享面板；Android 再加"存到手机文件夹" | 只用分享面板 | 有的 Android 手机的分享面板里没有"存到本机"，没装网盘的用户会存不下来 |
| 恢复方式 | 合并 | 清空本机后覆盖 | 覆盖时选错文件就会丢数据；合并不会丢 |
| 冲突时 | 保留本机 | 用备份覆盖 | 本机一般更新 |

## 风险和回滚

| 风险 | 处理 |
|---|---|
| 隐私政策写"不联网" | 备份文件只在用户点击时生成，交给用户选的 App，开发者收不到。`PRIVACY.md` 加一条说明 |
| 新的原生模块，Expo Go 里能跑，打包后才确认 | 都是 Expo Go 自带的模块；v1.2.0 的 APK 上做一次完整的备份→卸载→恢复 |
| 恢复了损坏或别人的文件 | 整份校验，不合法就拒绝；合并不删除本机记录 |
| 备份文件留在缓存目录 | 每次分享前删掉缓存里以前生成的 `ledger-*` 文件；恢复时选中文件的缓存副本读完就删 |
| Android 系统自动备份会把应用数据传到用户的 Google 云端硬盘，和"不上传"的说法不一致 | `app.json` 设 `android.allowBackup: false`。备份只走用户自己点的"备份到文件" |

回滚：删除「我的」标签页和三个依赖。备份文件格式一旦发出去，以后的版本要一直能读。

## 怎么验证

1. 单测：备份往返（导出再解析，记录一样）、各种坏文件、合并三种情况、CSV 转义和公式前缀、文件名。
2. 网页预览：「我的」页面显示正常；备份和导出能下载文件；恢复能选文件并合并。
3. v1.2.0 的 APK 上（打 tag 前用 preview 构建，或打 tag 后在 Release 的 APK 上）：
   - 备份 → 选"存到手机文件夹" → 选「下载」→ 在文件管理器里能看到文件；
   - 卸载 → 重装 → 恢复这个文件，记录都回来；
   - 再试一次"分享给其他 App"，能发到微信或网盘；
   - 导出 CSV，用 WPS 或 Excel 打开，中文正常。
